# 정규 어휘 사전 · 근거 없는 재작성 값 지우기

`backend/rag/query_analyzer/vocab.py` · 설정 `vocab_*` (configs/pipeline.yaml) · 테스트 `tests/query_analyzer/test_vocab.py`

## 왜

HCX 재작성은 질문에 없던 값을 만들어 낸다. 예를 들면 지표 칸에 '고령인구비율', 조건 칸에 '초혼', 대상 칸에 '한부모가구'가 들어간다.
지금까지 접지(`grounding.ground_slots`)는 이런 값을 "CSV 에 근거 없음" 메모로만 남기고 그대로 넘겼다.
그 값은 검색 문장, View 필터(`조건`은 View 가 분류·항목을 고르는 보조 단어), 재작성 문장(모듈 2·3 이 읽음)에 그대로 남았다.

이 패치는 **표 스키마(항목 이름 + 분류 코드 이름)로 "쓸 수 있는 말" 사전을 만들고**, 재작성 슬롯 값 중 이 사전과 질문 원문 어디에도
근거가 없는 값을 지운다(null).

## 사전 만들기

| 소스 | 무엇을 | 비고 |
|---|---|---|
| `VIEW_OUT_DIR/profiles/*.json` | items(지표) · levels.codes(분류·지역·성별·연령) | schema 1(`build_profile`)과 schema 2(`nm`·`role`·`additive`·`parallel`)를 모두 읽음. `levels` 가 dict 인 요약 파일은 건너뜀 |
| CSV 값 사전 (`values.parquet`) | 항목·분류 값 | 프로필이 없는 표까지 덮음. 같은 (슬롯, 분류 이름, 이름)은 한 줄로 합침 |
| `dictionary/vocab_aliases.csv` | 일상어 → 분류 코드 | 예: 싱글맘 → 세대구성별 '모+미혼자녀'. 뜻이 다른 말(미혼모)은 넣지 않음 |

```bash
python -m backend.rag.query_analyzer.vocab build                 # → CSV_INDEX_DIR/vocab.json (프로필 + CSV 값 사전)
python -m backend.rag.query_analyzer.vocab build --no-index      # 프로필만
python -m backend.rag.query_analyzer.vocab find 모+미혼자녀 가구원수
python -m backend.rag.query_analyzer.vocab check "2020년 세종 싱글맘 가정 식구" 대상=한부모가구 지표=가구원수
```

파일이 없으면 분석할 때 CSV 값 사전으로 바로 만든다(`settings.csv_scope`). 표가 1,092개쯤 되면 시간이 걸리므로 `build` 로 파일을 만들어 두는 것을 권한다.

사전 한 줄: `{name, norm, slot, dim, kind, unit, role, additive, is_total, codes, n_tables, tables}`.
`role`·`additive` 는 프로필에만 있다. 이 값은 [비공개 값 하한 계산](WITHHELD_VALUES_DESIGN.md)에서 "더해도 되는 수인가"를 판단하는 데 쓴다.

조회(`Vocab.lookup`)는 아래 순서로 한다. 슬롯마다 볼 사전 슬롯이 다르다. 대상·지표 칸은 지표·분류를, 조건 칸은 분류·지표를 본다.

1. 정확: norm 기준. 띄어쓰기, 구두점, `+()`, 코드 접두('03 동부')를 무시한다. 항목 + 단위도 정확 일치로 본다('1인'+'가구' → '1인가구').
2. 표기 변형: 괄호 단위를 빼거나, 끝의 '수'·'별'을 붙이거나 뺀다(`csv_index.store.variants`).
3. 핵심·어간: 계산 단어를 뺀 핵심과 그 어간이다. 예: '가구원수' ← '평균 가구원 수', '혼인' ← '혼인건수'.

## 판정 (`check_value`) — 대상 · 지표 · 조건 칸 (`vocab_slots`)

| 순서 | 근거 | 결과 |
|---|---|---|
| 0 | 숫자·빈 값, 되묻기에서 사용자가 고른 값 | 남김 (숫자 조건은 `drop_number_conditions` 가 다룸) |
| 1 | 계산 단어('비율'·'평균') · 일반 말('인구'·'가구') | 남김 (역할 단위·measure 가 다룸) |
| 2 | 사전에 그 슬롯으로 있음 (정확·변형·핵심) | 남김 |
| 3 | 별칭이거나, 질문 속 별칭의 정규 이름 | 남김 |
| 4 | 사전에 지역·성별로만 있음 (지표 칸의 '청양군') | **옮김** → 지역·성별 칸 |
| 5 | 질문 원문에 그 말이 있음 | 남김 (사용자가 쓴 말은 사전에 없어도 지우지 않음) |
| 6 | 용어 사전 · 검색 동의어가 질문의 말을 바꾼 값 ('결혼' → '혼인') | 남김 |
| 7 | Lexicon(rule · learned · csv · term>csv) 접지 — 포함 일치만은 아님 | 남김 |
| — | 그 밖 | **지움** |

질문에 별칭이 있으면(`vocab_alias_fill`) 정규 이름을 `조건`에 더한다. View 는 `조건`을 분류·항목을 고르는 보조 단어로 쓰므로
세대구성별 '모+미혼자녀' 코드가 골라진다.

## 분석 단계에서의 위치

`analyze`: 지역 칸 바로잡기 → 대상 원문 유지 → **근거 없는 값 지우기** → 대상 보충 → 시점 규칙 → 접지 …

- 본 슬롯과 하위 슬롯을 모두 판정한다. 별칭으로 조건을 더하는 것은 본 슬롯에만 한다.
- 무언가 바뀌면 `refresh_rewritten` 으로 재작성 문장도 다시 만든다. 모듈 2·3 이 이 문장을 읽기 때문이다.
- 대상·지표가 모두 지워지면 바로 다음 '대상 보충' 단계가 질문 속 CSV 표현으로 다시 채운다.
- 기록은 `notes` 의 `[어휘] [지표] '재혼율' 지움: …` 과 trace 단계 `근거 없는 값 지우기 (…)` 에 남는다.

설정 (configs/pipeline.yaml):

```yaml
vocab_check: drop          # drop / log(기록만) / off
vocab_slots: [대상, 지표, 조건]
vocab_alias_fill: true
vocab_path: ""             # 비우면 CSV_INDEX_DIR/vocab.json
```

평가 세트에서 처음 돌릴 때는 `vocab_check: log` 로 지워질 값을 먼저 보는 것을 권한다.

## 벡터 후보 — 사전에 없는 질문 낱말 (`vocab_suggest.py`)

사전 일치는 글자로만 맞춘다. 그래서 '모자가정'·'식구'처럼 표에 없는 일상어는 이어 주지 못한다.
벡터는 이 빈자리에서 **후보를 내는 데까지만** 쓴다. 비슷하다고 바로 바꾸지 않는 이유는 '미혼모'와 '모+미혼자녀', '1인가구'와 '2인가구'처럼 가깝지만 뜻이 다른 값이 많아서다.

```
질문 낱말 ─ 사전·별칭·CSV·슬롯에 있음 ─▶ (끝)
          └ 없음 ─▶ 학습 사전에 승인된 짝? ─ 예 ─▶ 바로 적용
                    └ 아니오 ─▶ 벡터 후보 top-k (점수 하한)
                                 ├ log : 후보만 기록 (응답 vocab_suggestions · notes · trace)
                                 └ hcx : HCX 가 후보 목록 안에서 '같은 뜻'만 고름 (없으면 0)
                                         └ 고른 짝 → 슬롯에 더함 + 학습 사전 '승인 대기'
사람이 승인 (POST /api/v1/rag/lexicon/learn approve=true 또는 lex.approve) ─▶ 다음부터는 HCX·벡터 없이 적용
```

- **고를 낱말:** 질문을 띄어쓰기로 나누고 조사를 뗀 낱말이다. 다음은 빼고 최대 `vocab_suggest_max_terms` 개를 고른다.
  - 두 글자 미만, 숫자·때
  - 물음·지시 말('몇', '알려줘'), 풀이말('합치면', '키우는')
  - 계산 단어·일반 말, 지역·성별
  - 사전·별칭·CSV(포함 일치 제외)에 있는 말, 슬롯 값과 서로 포함 관계인 말
- **벡터 파일:** 사전의 지표·분류 이름을 한 번 임베딩해 `vocab.json` 옆 `vocab_vectors.<임베더>.npz` 에 둔다. 합계('계')와 지역은 넣지 않는다. 분류 코드는 분류 이름과 함께 임베딩한다('세대구성별 모+미혼자녀').
  분석할 때는 질문 낱말만 임베딩한다. 파일이 없거나 만든 임베더가 지금과 다르면 건너뛰고 trace 에 사유를 남긴다. 사전을 다시 만들어도 파일은 그대로 쓰고, 지금 사전에 없는 줄만 후보에서 뺀다.
- **HCX 고르기:** 낱말마다 번호 붙인 후보만 보여 주고 번호나 0을 받는다. 후보 밖 번호, 묻지 않은 낱말, 오류는 모두 '고르지 않음'으로 처리한다.
  고른 결과는 `state.vocab_choices` 에 남는다. 그래서 되묻기 응답(previous)에서는 HCX 를 다시 부르지 않는다.
- **더하는 곳:**
  - 분류 코드 → `조건` (View 가 그 코드를 고른다)
  - 항목 → 대상·지표가 사전에 근거가 없을 때만 `지표`. 근거가 이미 있으면 더하지 않는다(서브쿼리가 늘지 않게). 이 경우 기록만 남는다.

```bash
python -m backend.rag.query_analyzer.vocab build --embed hcx              # 사전 + 벡터 (HCX 임베딩은 sqlite 캐시)
python -m backend.rag.query_analyzer.vocab embed --embed bge-m3-ko        # 지금 사전으로 벡터만 (로컬 모델)
python -m backend.rag.query_analyzer.vocab suggest "세종 모자가정 가구 수" --mode hcx --min-score 0.5
```

```yaml
vocab_suggest: log               # off / log / hcx
vocab_suggest_embedder: hcx      # 벡터 파일을 만든 임베더와 같아야 함
vocab_suggest_k: 5
vocab_suggest_min_score: 0.55    # 임베더마다 분포가 다름 — log 로 후보 점수를 보고 정한다
vocab_suggest_max_terms: 3
vocab_suggest_learn: true        # hcx 가 고른 짝 → 학습 사전 '승인 대기'
```

권하는 순서는 이렇다.
1. `log` 로 평가 세트를 돌려 `vocab_suggestions` 의 후보와 점수를 본다. 이때 하한과 k 를 정한다.
2. `hcx` 로 바꾼다.
3. 쌓인 '승인 대기'(`GET /api/v1/rag/lexicon/pending`)를 사람이 승인한다.

승인된 짝은 이후 별칭처럼 바로 쓰인다.

## 예

| 질문 | 재작성 슬롯 | 결과 |
|---|---|---|
| 2023년 서울 혼인 건수 | 지표 [혼인건수, 재혼율] · 조건 [초혼] | 지표 [혼인건수]. '재혼율'·'초혼' 지움 |
| 청양군 인구 비율 | 지표 [청양군, 비율] | 지역 [청양군] · 지표 [비율] |
| 2020년 세종의 싱글맘 가정 식구를 다 합치면 몇명이나 되? | 대상 [한부모가구] · 지표 [가구원수] | 지표 [가구원수] · 조건 [모+미혼자녀]. 재작성 문장 '2020년 세종 모+미혼자녀 가구원수' |

'한부모가구'는 테스트 사전에 없어서 지워졌다. 실제 1,092개 표 사전에 그 항목이 있으면 남는다. 판정은 사전에 따라 달라진다.

## 한계

- 사전에 있는 이름이지만 질문과 뜻이 다른 값은 막지 못한다. 예: '노인 수'를 물었는데 '고령인구비율'이 나온 경우다. 이 값은 사전에도 있고 용어 사전도 이어 준다.
  이런 값은 "근거 없음"이 아니라 "의도 불일치"이므로 measure·역할 단위 쪽에서 다뤄야 한다.
- '질문 원문' 근거는 글자 포함으로 본다. 그래서 질문의 짧은 말과 겹치는 지어낸 값은 남을 수 있다.
- 별칭 파일은 작게 시작했다. 넣는 기준은 "표의 분류 코드와 뜻이 같은 말"이다. 벡터 후보 → HCX → 승인으로 쌓이는 학습 사전이 별칭 파일을 보완한다.
- 벡터 후보 낱말은 띄어쓰기 단위로 고른다. 그래서 여러 낱말로 된 말('엄마 혼자 키우는')은 별칭 파일로 다룬다.
- 로컬 임베딩 모델·HCX 임베딩의 실제 점수 분포는 이 패치에서 확인하지 못했다(테스트는 가짜 임베더). 하한은 `log` 로 보고 정해야 한다.
