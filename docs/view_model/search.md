# search.py — ③ 자연어 검색 (+ table_text.py 표 색인, embedding.py 임베딩)

> **방식 변경 (2026-11-02 오후)**: 동시 결합(RRF) → **순차**.
> 1단계 BM25(kiwi 형태소)로 989개 중 상위 10개 → 2단계 그 10개만 bge-m3(HCX) 코사인 유사도로 다시 줄 세움 → 상위 3개로 View.
> 이유: 본 프로젝트에서 raw 데이터 전체로 늘어나면 dense 를 모든 표에 계산하기 느리므로 싼 BM25 로 먼저 좁힌다.
> 결과 항목: `rank`(재정렬 순위), `dense`(=`score`), `bm25_rank`·`bm25`(1단계). 아래 3장의 RRF 설명은 이전 방식 기록이다.

## 한눈에 보기

| | |
|---|---|
| **하는 일** | 쿼리 모듈이 보낸 **자연어**로 메타데이터(표 설명문 989개)를 검색해 상위 `top_k`(기본 10)개를 순위대로 돌려준다 |
| **검색 방식** | bge-m3 임베딩(HCX API) 코사인 유사도 + BM25(kiwi 형태소) → 두 순위를 **RRF** 로 결합 |
| **하지 않는 것** | 표를 하나로 확정하지 않는다 (맞는지는 판단 모듈이 판단). 슬롯(지역·시점)은 검색에 쓰지 않는다 (View 를 자를 때 씀) |
| **실행** | API `POST /search`, 색인 `POST /search/index/build`·`GET /search/index/status` · CLI `cd view_model && ../.venv/Scripts/python.exe -m services.search "질의"` |
| **코드 위치** | `services/embedding.py`(HCX 임베딩), `services/table_text.py`(설명문·색인), `services/search.py`(검색), API `routers/search.py` |

```
[한 번만] meta_profiles.jsonl ─ table_text() ─▶ 표 설명문 989개 ─┬ bge-m3(HCX) ─▶ dense.npy (989 × 1024)
                                                                └ kiwi ───────▶ tokens.json (BM25)
[질의마다] 자연어 ─┬ bge-m3(HCX) ─▶ 코사인 유사도 ─▶ dense 순위 ─┐
                  └ kiwi + BM25 ─────────────────▶ BM25 순위 ──┴▶ RRF ─▶ 상위 10개
```

## 1. 임베딩 (`services/embedding.py`)

| 항목 | 값 |
|---|---|
| API | CLOVA Studio 임베딩 v2 `POST {호스트}/v1/api-tools/embedding/v2`, body `{"text": ...}` (한 번에 1문장) |
| 모델 | bge-m3 기반, **1024차원**, 입력 약 8k 토큰 (6000자에서 자름) |
| 인증 | `.env` 의 `HCX_API_KEY` (Bearer). 호스트는 `HCX_BASE_URL` 에서 호스트 부분만 |
| 캐시 | `output/embed_cache.sqlite` — (모델, 문장) 이 같으면 다시 호출하지 않음. 중단 후 다시 실행하면 남은 것만 |
| 재시도 | 429·5xx·네트워크 끊김은 점점 길게 기다리며 최대 8회, 400 등은 즉시 중단 |
| 속도 (2026-11-02) | 1건 약 0.4초. 4개 동시 호출 시 처음 2.5건/초 → 속도 제한(429) 후 약 1건/초 |
| 제약 | API 는 **dense 만** 준다 (bge-m3 의 sparse 없음) → 키워드 쪽은 BM25 로 보완 |

공용 `kosis_rag_qa.py` 와 같은 방식이지만 **import 하지 않는다** — import 하면 캐시가 공용 폴더 `kosis_data/index/` 에 써지기 때문.

## 2. 표 설명문과 색인 (`services/table_text.py`)

설명문 = **"이 표가 무엇을 세었는가"**. 예 (`DT_1B040A3`):

```
주민등록인구현황 | 행정구역(시군구)별, 성별 인구수
분류: 행정구역(시군구)별(시도·시군구)
항목: 총인구수, 남자인구수, 여자인구수
단위: 명
기간: 월 2011~2026; 년 1992~2025
경로: 주민등록인구현황
```

| 넣는 것 | 넣지 않는 것 (이유) |
|---|---|
| 조사명, 표 이름, 분류 이름, 지역 **수준**(시도·시군구), 코드 30개 이하 분류의 코드 이름(성별·종류 …), 항목, 단위, 기간 범위, 메뉴 경로 | 지역 코드 수천 개, 연도 목록 (설명문이 길어지고 모든 표가 비슷해짐. 어디·언제는 View 생성이 정확히 처리) |

- 원본 CSV 가 없는 표 3개는 색인에서 뺌 (골라도 View 를 못 만듦) → **989개**
- 설명문 길이: 중앙값 약 250자, 최대 약 900자
- 출력 `output/table_index/`: `ids.json`, `texts.jsonl`, `tokens.json`, `meta.json`(표 수·생성 시각). 순차 방식으로 바꾸면서 989개 전체 임베딩(`dense.npy`)은 만들지 않음 — 뽑힌 10개만 검색 때 임베딩(캐시 사용)
- **메타데이터 구조는 초안**이라 바뀌면 `table_text()` 만 고치고 색인을 다시 만든다 (`POST /search/index/build`). 바뀌지 않은 설명문은 캐시로 바로 끝난다

## 3. 검색 (`services/search.py`)

| 단계 | 내용 |
|---|---|
| dense | 질의 임베딩(정규화) · 표 임베딩 행렬 → 코사인 유사도 → 순위 |
| BM25 | 질의를 kiwi 로 명사·어근 등만 남겨 BM25 점수 → 순위 (겹치는 단어가 없는 표는 BM25 점수 없음) |
| RRF | 표마다 `1/(60 + dense 순위) + 1/(60 + BM25 순위)` → 큰 순 상위 `top_k` |

- 왜 RRF: 코사인 유사도와 BM25 점수는 크기가 달라 그대로 더할 수 없음. 순위만으로 합치면 척도 문제가 없다 (k = 60, 공용 코드와 같은 값)
- 왜 BM25 를 같이: "출생아수"처럼 표 이름에 그대로 있는 단어는 BM25 가 정확하고, "평균 수명 ↔ 기대수명" 처럼 표현이 다른 경우는 임베딩이 잡는다
- 색인 모델과 질의 모델이 다르면 오류 (벡터 공간이 달라 비교가 무의미)

### 결과 항목 (`Candidate`)

| 필드 | 의미 |
|---|---|
| `rank` | RRF 순위 |
| `score` | RRF 점수 |
| `dense` | 자연어 ↔ 표 설명문 코사인 유사도 |
| `bm25_rank` | BM25 순위 (겹치는 단어가 없으면 null) |
| `has_view` | /views 에서 View 를 만들었는지 |

## 4. 검색 결과와 진단 (2026-11-02, 예시 12개 · 검색 단위 16개, 상위 3개 기준)

| 질의 | 상위 후보 | 평가 |
|---|---|---|
| 3 출생아수 추이, 4 신생아 수 | 인구동향조사 출생아수·동태건수 표 | 맞음 |
| 6-2 대구 사망자 수 | 시군구 월별 사망자수, 시도 사망자수 | 맞음 |
| 8 평균 수명, 11-1 기대수명 | 장래·실측 기대수명 표가 1~2위 | 맞음 (실측/장래 구분은 판단 모듈) |
| 9 부산 1인 가구 | 1인가구 표들 | 맞음 |
| 11-2 고령인구비율 | 주요 연령계층별 추계인구(고령인구) | 맞음 |
| 12 대전 인구 변화 | 대전광역시 총조사인구 총괄 | 그럴듯 (단, 1990~2010 표) |
| **1·2 대구 인구, 5 시도별 인구** | 인구총조사 **이동인구** 표 | 엉뚱함 |
| **6-1 부산 출생아 수** | 출생아수별 **부인수** 표 | 엉뚱함 |
| **7 노인 비율, 10 경기도 가구 수** | 관련 낮은 표 | 약함 |

### 진단: "인구" 처럼 흔한 단어만 있는 질의가 약하다

기본 인구 표 `DT_1B040A3`(시군구별 성별 인구수)의 순위:

| 질의 | dense 순위 | BM25 순위 |
|---|---|---|
| 작년 대구 인구 수 | 300 | 26 |
| 최근 5년간 대전의 인구 변화 추이 | 340 | 559 |
| 2023년 시도별 인구 | 494 | 222 |

- **BM25**: 수백 개 표가 '인구총조사'·'인구' 를 공유해 변별력이 없다
- **dense**: 설명문이 모든 표에 같은 틀(`분류: / 항목: / 기간: / 경로:`)이고, 내용이 짧은 표는 틀과 기간 숫자가 대부분이라 임베딩이 내용보다 형식에 끌리는 것으로 **추정** (설명문 형식을 바꿔 비교해 봐야 확인됨)
- 메타데이터(초안) 설계 문제라 아직 고치지 않았다. 개선 후보: 설명문을 자연어 문장으로, 틀 문구·기간 숫자 줄이기, 표 단위 외에 "표 × 주요 분류" 단위 메타데이터 추가 등
