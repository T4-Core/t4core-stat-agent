# query_bundle.py — ② 슬롯 질의 파싱 (보조) · 예시 질의

> **역할 변경 (2026-11-02)**: 쿼리 모듈은 **자연어 + 슬롯 dict** 를 함께 보낸다. 검색은 자연어로, 슬롯은 View 조건으로 쓴다.
> 그래서 이 파일의 슬롯 문자열 파서는 **슬롯이 문자열로만 왔을 때 dict 로 바꾸는 보조** 역할이다.
> 예시 12개는 `example_queries()` 가 View 모듈 입력 형식(자연어 `original` + 슬롯 dict `filters`, 서브쿼리도 자연어 + 슬롯)으로 만든다.
> 아래 5장의 "resolve" 는 그 뒤 `build_view`(View 생성)로 바뀌었다 → `docs/build_view.md`

## 한눈에 보기

| | |
|---|---|
| **하는 일** | 쿼리 모듈이 재작성한 슬롯 형식 질의(`[시점] 2025년 [지역] 대구광역시 …`)를 **QueryBundle**(팀 스펙)로 바꾼다. `filters`·`sub_filters`·`intent` 를 채움 |
| **입력** | `original`(사용자 원문), `rewritten`(슬롯 형식), `sub_questions`(하위 질의, 슬롯 형식) |
| **출력** | `QueryBundle` + `notes`(해석하지 못한 부분) |
| **실행** | API `POST /query/bundle`, `GET /query/examples` · CLI `cd view_model && ../.venv/Scripts/python.exe -m services.query_bundle` |
| **코드 위치** | 로직 `services/query_bundle.py`, API `routers/query.py`, 예시 입력 `data/slot_queries.json` |
| **외부 호출** | 없음 (LLM·임베딩 사용 안 함, 규칙만) |

```
"[시점] 2025년 [지역] 대구 [연령] 20~29세 [지표] 인구수 [의도] 값 조회"
      │ SLOT_RE 로 [이름] 값 쌍 추출
      ▼
 시점 → [2025]          지역 → std_geo_name → ["대구광역시"]     연령 → parse_age → {from:20, to:29}
 지표 → ["인구수"]       의도 → "값 조회" (intent 에도)
      │
      ▼
QueryBundle {original, rewritten, sub_questions, intent, filters, sub_filters} + notes
```

---

## 1. 원칙

1. **파싱만 한다. 기본값은 채우지 않는다.** 빈 슬롯은 `null`.
   "시점이 없으면 최신 연도"는 **표마다 최신 연도가 달라서** 표를 고른 뒤 ③ resolve 가 적용한다.
2. **데이터 쪽 표기와 같은 규칙을 쓴다.** 지역 표준명은 `normalize.std_geo_name`, 연령 범위는 `normalize.parse_age` 를 그대로 호출.
   그래서 질의의 "대구"와 데이터의 `대구광역시`, 질의의 `20~29세`와 데이터의 `20 - 24세` 가 같은 기준으로 비교된다.
3. **버리지 않고 남긴다.** 모르는 슬롯, 해석 못 한 값, 지역명을 바꾼 내역은 모두 `notes` 로.
4. **실패 규칙은 팀 스펙 그대로.** 슬롯이 하나도 없으면 `rewritten = original`, `sub_questions = []`, `intent = filters = null`.

## 2. 슬롯별 규칙

| 슬롯 | 예 | 결과 | 규칙 |
|---|---|---|---|
| 시점 | `2025년` / `2021년, 2022년` / `2021~2023년` | `[2025]` / `[2021, 2022]` / `[2021, 2022, 2023]` | 연도 정수 목록, 범위는 펼침. `최근 5년` 같은 상대 표현은 해석하지 않고 notes (쿼리 모듈이 연도로 바꿔 줘야 함) |
| 지역 | `대구`, `부산광역시, 대구광역시` | `["대구광역시"]`, `[…]` | 표준명으로 (`region_dict.json` 과 같은 사전). 바꾼 내역은 notes |
| 연령 | `20~29세` / `65세 이상` / `15세 미만` | `{20, 29}` / `{65, null}` / `{0, 14}` | 여러 값은 **이어지거나 겹칠 때만** 합침. 떨어진 범위는 `null` + notes |
| 성별 · 대상 · 지표 | `남자, 여자` | `["남자", "여자"]` | 쉼표로 나눈 목록 (그대로) |
| 비교축 · 의도 | `시도`, `값 조회` | `"시도"`, `"값 조회"` | 문자열. 의도는 `intent` 에도 |
| 그 외 | `[기준] 실측` | (Filters 에 없음) | notes: "모르는 슬롯 … 쿼리 모듈과 협의 필요" |

## 3. 코드 구성

| 함수 | 하는 일 |
|---|---|
| `split_values(text)` | 쉼표(`,`, `，`, `、`)로 값 나누기 |
| `parse_years(values, notes)` | 시점 → 연도 목록 |
| `parse_ages(values, notes)` | 연령 → `{from, to}`. 떨어진 범위 검사 |
| `parse_slots(text)` | 슬롯 문자열 하나 → `(filters, notes)`. 슬롯이 없으면 `(None, …)` |
| `build_bundle(original, rewritten, sub_questions)` | QueryBundle(dict) + notes. 하위 질의도 각각 파싱해 `sub_filters` |
| `load_examples()`, `example_bundles()` | `data/slot_queries.json` 의 12개 예시 읽기·파싱 |

### API

| 경로 | 설명 |
|---|---|
| `POST /query/bundle` | 입력 `SlotQuery{original, rewritten, sub_questions}` → `QueryBundleResult{bundle, notes}` |
| `GET /query/examples` | 12개 예시 파싱 결과 `[{query_id, sub_ids, bundle, notes}]` |

`bundle` 은 팀 스펙 QueryBundle 그대로이고, `notes` 는 바깥에만 붙였다 (팀 스펙을 바꾸지 않기 위해).

### 예시 입력 `data/slot_queries.json`

쿼리 모듈 담당자가 준 12개 질의. `original` = 베이스라인 문장, `rewritten` = 슬롯 형식, `sub_ids`·`sub_questions` = 하위 질의(6번, 11번).
`query_id` 는 나중에 Record `id`(`질의ID::하위ID::표key`)에 쓰인다. 질의문만 옮겼고 11/1 실험 결과값은 넣지 않았다.

## 6. 쿼리 모듈과 협의할 것

- `[기준]` 슬롯 (실측/추계) 추가 여부
- 상대 시점(`최근 5년`, `작년`)은 쿼리 모듈이 연도로 바꿔서 보내는지 (예시 12개는 이미 바꿔서 옴)
- 떨어진 연령 범위 여러 개가 필요한 질의가 있는지 → 있으면 `Filters.연령` 을 목록으로 바꿔야 함
