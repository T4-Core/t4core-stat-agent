# resolve — 검색 후보가 슬롯 조건을 담고 있는지 확인하고 다시 줄 세우기

코드: `backend/rag/ingestion/resolve.py` · 연결: `backend/rag/retrieval/table_search.py` `search(filters=…)`, `backend/rag/ingestion/views.py` `run_query`

## 1. 요약

검색이 표 이름 단어만 보고 고르던 것을, **"이 표에 요청한 시점·지역·성별·연령·지표가 있나"** 를 메타 프로필로 확인해 조건을 많이 맞춘 표부터 고르게 한다.

```
자연어 + 슬롯
  → search_query : 지역·시점 단어 빼고(A), 슬롯 지표·대상 단어 더함(C)
  → BM25 상위 50개
  → rerank       : 표마다 unmet(못 맞춘 조건) → 적은 순 (같으면 BM25 순)
  → 상위 10개만 bge-m3 → 최종 순서 = (못 맞춘 조건 수, dense)
  → 상위 3개로 View
```

함께 바꾼 것 (B): `table_text.py` — 지역으로 판정되지 않은 분류·항목이라도 시도 이름이 3개 이상이면 이름을 나열하지 않고 `(지역·시도)` 로만 적음 (40개 표 설명문 변경).

## 2. 왜

변경 전 BM25 는 시점·지역을 전혀 보지 않고 단어 점수 합으로 상위 10개를 잘랐다. 질의 1 `작년 대구의 남자 20대 인구 수`:

| 표 | 점수가 나온 단어 | 합계 | 순위 |
|---|---|---|---|
| 1인이동건수 `DT_1B26B24` | `대` 7.62 ('20대' 에서 떨어진 한 글자) | 11.34 | 1 |
| 1985 이동인구 `DT_1MI8506` | `대구` 4.69 (설명문의 '대구직할시') | 8.31 | 6 |
| 주민등록 5세별 인구 `DT_1B04005N` | 인구·20·수 (설명문에 지역 이름 없음) | 4.86 | 42 |

→ 정답에 가까운 표가 10개 안에 못 들어와 dense 재정렬로도 못 살림.

## 3. 조건 확인 규칙 (`unmet`)

| 조건 | 맞춤 판정 (메타 프로필만, 원본 CSV 안 읽음) |
|---|---|
| 시점 | 요청 연도가 모두 표 기간 안 / 연도를 안 물었으면 끝 연도 ≥ `LATEST_FROM`(2024) |
| 지역 | 요청 시도가 분류 코드·항목 이름에 있음 (`대구광역시`·`대구`·옛 `대구직할시` 같은 시도로 봄) / `비교축` 시도·지역이면 시도 이름 10개 이상 |
| 성별 | 성별 분류가 있거나, 항목·코드 이름에 남자/여자 |
| 연령 | 연령 분류가 있거나, 이름에 `N세`·`N~M` |
| 지표 | 지표 단어(`인구수` → `인구수`·`인구`)가 표 이름·항목·코드 이름에 있음 |

표는 버리지 않고 순서만 바꾼다. 못 맞춘 조건은 후보의 `unmet` 에 남는다 (`/views/detail` 의 `candidates[].unmet`).
`filters` 를 넘기지 않으면 `search()` 는 예전과 같다 (BM25 상위 top_k → dense).

### 4-1. 연령 표현도 검색어에서 빼기

`20대` 의 뜻(20~29세)은 쿼리 모듈이 이미 슬롯 `연령: {from: 20, to: 29}` 로 넘겨준다. 검색어에서 빼도 resolve(연령 구분 확인)·build_view(`20~24세`·`25~29세` 코드 고르기)는 슬롯을 쓰므로 정보가 사라지지 않는다.

- 슬롯에 `연령` 이 있을 때만 뺌: `N대` · `N세 (이상|이하|미만|초과)` · `N~M세`
- `노인`·`고령` 처럼 숫자 없는 말은 남김 (어떤 표인지 알려 주는 단어)

| | 검색 문장 | 상위 3개 |
|---|---|---|
| 전 | `남자 20대 인구 수` | `DT_1B04005N`(2025) · `DT_1IN6601`(1966) · `DT_1IN0504`(2005) |
| 후 | `남자 인구 수` | `DT_1B04006`(2025, 1세별 10행) · `DT_1B04005N`(2025, 5세별 2행) · `DT_1B040A3`(2025, unmet: 연령 구분 없음) |

| | 원래 | A·B·C | + 연령 |
|---|---|---|---|
| 조건을 다 맞춘 View | 18 | 39 | **40** |
| notes 합계 | 55 | 17 | **11** |

### 4-2. 시점은 "몇 개나 담았나" 비율로 (cost)

KOSIS 는 같은 내용이 시기별로 나뉜 표가 많다 (`총조사인구(2015년 이후)` / `2010년 이전` 등, 이름·경로에 연도 구간이 있는 표 180개 — 메타 기간과 모두 일치).
연도 하나를 물으면 기간 확인만으로 맞는 시기의 표가 골라진다 (검색 문장에 연도를 넣지 않아도 됨: 글자로 후보를 모으고, 연도는 숫자로 비교).

문제는 여러 시기에 걸친 추이: 요청 연도를 "다 담았나 / 아니오" 로만 세면 6개 중 4개 담은 표와 0개 담은 1935년 표가 똑같이 "못 맞춤 1개".

```
cost = 시점 외 못 맞춘 조건 수 + (1 - cover)      cover = 요청 연도 중 표 기간 안에 든 비율
```

`성 및 연령별 인구 추이` (2000~2025, 5년 간격):

| | 1위 | 2위 | 3위 |
|---|---|---|---|
| 전 | `DT_1IN1003` (2010) | `DT_1IN3504` (**1935**) | `DT_1IN3003` (**1930**) |
| 후 | `DT_1B04006` (2008~2025, cover 0.67) | `DT_1IN1503` (2015~2025, 0.5) | `DT_1IN1003` (2010, 0.17) |

함께 고친 것: 연도 뒤 `부터·까지·이후·이전·~` 도 검색어에서 뺌 (`2000년부터 대전 인구 추이` → `인구 추이`).
예시 12개: 질의 12 의 3위만 `DT_1B8000F`(대전 없음) → `DT_1BPB004`(cover 0.8). 합계는 40 / 11 / 0 그대로 (예시에 시기가 갈리는 추이 질의가 거의 없음).

다음 후보: 시기가 다른 표를 짝지어 빈 연도를 채우기 (2010 이전 표 + 2015 이후 표). 두 표는 조사 기준이 달라 이어 붙이면 단절이 생기므로 판단 모듈과 넘기는 방식을 먼저 정해야 함.
