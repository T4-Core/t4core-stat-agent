# 비공개(X) 값이 섞인 계산 — 하한과 범위로 밝히기 (설계 메모 · 모듈 3·6 참고용)

> **이 문서는 참고용이다. 이 패치는 Agent 모듈(chart_calculate · answer_compose) 코드를 바꾸지 않는다.**
> 아래 수치는 업로드된 `101_DT_1JC1516` processed parquet 에서 직접 확인했다.

## 지금 동작

1. 정규화: KOSIS 의 `X`(비밀보호) 칸은 `value = NaN`, `value_raw = "X"`, `symbol = "X"` 이다. View 에는 `부호` 열로 실린다(`view/build.py`).
2. 모듈 3 `select_rows`: 값이 빈 행은 `rows` 에서 빼고 `dropped` 에 넣는다. Series 노트에는 "값이 비어 제외한 행 N개" 가 붙는다.
3. `aggregate(sum)`: 남은 점만 더한다. **결과는 공개된 칸만의 합(하한)인데, 답변에는 그냥 '값'으로 나갈 수 있다.**
4. 평균 × 가구 수로 사람 수를 구하면 평균이 반올림돼 있어서 수백 명이 틀린다.

## 사례 — "2020년 세종의 싱글맘 가정 식구를 다 합치면?"

세대구성별 '모+미혼자녀' · 세종특별자치시(29). 세종시(29010)는 같은 값이 한 번 더 있으므로 하나만 쓴다.

| 항목 | 1인 | 2인 | 3인 | 4인 | 5인 | 6인 | 7인 이상 | 일반가구(계) | 평균 가구원 수 |
|---|---|---|---|---|---|---|---|---|---|
| 가구 | X | 5,110 | 2,827 | 427 | 33 | X | X | 8,402 | 2.5 |

- 공개된 칸의 가구 합은 8,397이다. 계가 8,402이므로 **비공개 칸 셋(1인·6인·7인 이상)에 합쳐서 5가구**가 있다.
- 공개된 칸의 사람 수는 Σ(크기 × 가구) = 2·5,110 + 3·2,827 + 4·427 + 5·33 = **20,574명**이다.
- 비공개 5가구로 정해지는 범위:
  - 산술 하한: 5가구가 모두 1인이면 +5 → 20,579.
  - 평균 제약: 2.5 는 [2.45, 2.55) 를 반올림한 값이다. 그래서 사람 수는 2.45 × 8,402 = 20,584.9 이상이고, 2.55 × 8,402 = 21,425.1 미만이다.
  - 둘을 합치면 **20,585 ~ 21,425명**이다.
  - 도메인 규칙('모+미혼자녀'에 1인 가구는 없다)을 쓰면 5가구는 모두 6인 이상이다. 그러면 하한은 20,604명이다. 7인 이상을 7명으로 보면 20,609명이다.
- 평균 × 가구 = 2.5 × 8,402 = 21,005명이다. 반올림 때문에 폭이 ±420명쯤이라 대표값으로 쓰면 안 된다.

**잔차가 0이면 정확한 값이다.** '부+미혼자녀'는 공개 칸 합(1,892 + 891 + 135 + 6 = 2,924)이 계(2,924)와 같다.
따라서 비공개 칸은 모두 0이고, 사람 수 7,027명은 **정확한 값**이다. 확인하면 평균 7,027 / 2,924 = 2.40 → 2.4 로 맞는다.

## 제안 — 모듈 3 (chart_calculate)

`aggregate(sum)`·`combine` 의 피연산자에 `부호 = X` 로 빠진 행(`dropped`)이 있으면 결과 점 하나를 아래처럼 만든다.

```text
Point.value      = 공개 칸 합 (지금과 같음)
Calc.bound       = {"kind": "lower" | "range" | "exact",
                    "lower": …, "upper": … | None,
                    "withheld": [{"key": {...}, "symbol": "X"}],
                    "residual": 계 − 공개 칸 합 (계 행이 View 에 있을 때),
                    "basis": ["공개 칸 합", "계와의 차", "평균 반올림 범위"]}
```

1. **잔차**: 같은 분류에서 `is_total` 인 계 행(또는 `additive` 항목의 계)이 View 에 있으면 `residual = 계 − Σ공개`.
   잔차가 0이면 `exact`(비공개 칸 = 0)이다. 잔차가 0보다 크면 비공개 칸 전체의 합이 정해진다.
2. **가중 합**(사람 수 = Σ 크기 × 가구): 크기는 항목 이름에서 읽는다('N인', 'N인 이상'). 잔차 r 가구에 대해:
   - 하한 = Σ공개 + r × (비공개 칸 중 가장 작은 크기)
   - 상한 = 열린 칸('7인 이상')이 없으면 Σ공개 + r × (가장 큰 크기)이고, 있으면 없음(None)
3. **평균 제약**: 같은 분류에 `role = mean` 항목(평균 가구원 수)이 있으면 반올림 자릿수 d 로
   `[(m − 0.5·10^-d) × 계, (m + 0.5·10^-d) × 계)` 를 구해 2번 범위와 교집합을 낸다.
4. 더할 수 없는 값(`additive = false`, 비율·평균)에는 하한을 만들지 않고 지금처럼 '계산 불가 + 사유'로 둔다.

필요한 정보(`additive`, `role`, `is_total`)는 정규 어휘 사전(`vocab.json`)과 프로필에 이미 있다. 모듈 3 은 View 의 `부호` 열과 프로필을 함께 보면 된다.

## 제안 — 모듈 6 (answer_compose)

- `bound.kind == "exact"`: 지금처럼 값을 말한다. 주의사항은 없다.
- `bound.kind == "lower"`: "**최소 20,585명**입니다(비공개 3칸 제외)"처럼 하한이라고 밝힌다.
- `bound.kind == "range"`: "**20,585 ~ 21,425명**입니다. 6인·7인 이상 가구 수는 비밀보호(X)로 공개되지 않아, 공개된 2~5인 가구와 평균 가구원 수(2.5명)로 범위를 구했습니다."

  Streamlit `answer_card` 의 주의사항 중복 표시 문제와 겹치지 않게, 답변 문장에 이미 쓴 내용은 caveats 에서 빼는 규칙을 같이 정한다.
- 자리표시자 검사(placeholder.py)는 하한·범위 숫자도 계산 결과의 인용으로 인정해야 한다. 예: `{a1.lower}` · `{a1.upper}`.
